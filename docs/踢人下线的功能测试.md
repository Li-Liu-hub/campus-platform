## 二、踢人下线后的 Redis 数据

### Redis 连接信息

```text
地址：127.0.0.1:6380
逻辑数据库：DB 0
扫描结果：7 个键
```

Redis 中只剩下 1 个账号会话键和 6 个 Token 映射键。

### 1. 被踢用户的账号会话已删除

被踢用户的账号会话键：

```text
Authorization:login:session:2092954516224405506
```

查询结果：

```text
EXISTS Authorization:login:session:2092954516224405506
结果：0
```

说明：用户 `2092954516224405506` 的 `Account-Session` 已从 Redis 删除，原账号会话中的全部终端信息也随之删除。

### 2. 被踢用户的 Token 映射全部变为负数

| Token | Redis 中的值 | 结果 |
| --- | ---: | --- |
| `0f05e9fe-5086-4a55-bf51-004b2968ae0d` | `-5` | 已失效 |
| `236373ca-76ec-4069-a854-24aa897c265d` | `-5` | 已失效 |
| `a2cd7926-71e6-44b1-8c70-0e4d2b8d2f1b` | `-5` | 已失效 |
| `66c2b715-c545-4343-9f62-2cfe59613791` | `-4` | 已失效 |
| `be597be4-7665-49b7-b2d7-b7254726137c` | `-4` | 已失效 |

对应的 Redis 键格式为：

```text
Authorization:login:token:<Token>
```

本次踢人下线后，被踢用户的 5 个 Token 映射均不再保存用户 ID，而是保存负数状态码，因此这些 Token 均不能继续通过鉴权。

## 三、测试结论

本次测试结果如下：

1. 管理员踢人接口返回 HTTP 200，操作成功。
2. 被踢用户 `2092954516224405506` 的账号会话键已删除。
3. 被踢用户的 5 个 Token 映射全部变为负数：`-5` 或此前已被替换产生的 `-4`。
4. 被踢用户的所有 Token 均已失效，不能继续访问需要登录的接口。
5. 其他用户的账号会话和 Token 不受影响。
