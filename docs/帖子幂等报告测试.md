# 帖子幂等并发测试

## 测试目标

验证并发场景下多个请求携带同一幂等键创建帖子时，数据库中只会落库一条记录：唯一索引兜底防止重复插入，冲突请求返回已存在的原帖子。

## 测试环境

```text
应用地址：http://localhost:8080（Docker 容器 campushub-app）
数据库：MySQL 8.4，campushub 库 ch_post 表
压测工具：JMeter
```

## JMeter 配置

### 线程组

| 配置项 | 值 |
| --- | --- |
| 线程数 | 8 |
| Ramp-Up 时间（秒） | 1 |
| 循环次数 | 1 |

8 个线程在 1 秒内并发启动，每个线程发送 1 次请求。

### HTTP 请求

```text
请求方法：POST
请求地址：http://localhost:8080/api/v1/posts/create
内容编码：UTF-8
```

### 请求头

| 参数名 | 参数值 |
| --- | --- |
| Authorization | Bearer c847330d-f5d1-4c9c-9718-8064b3ec00b7 |
| Content-Type | application/json |

8 个线程使用同一用户 Token，共用同一幂等键。

### 请求体

```json
{
    "postTitle": "并发测试",
    "postType": "其他内容",
    "postText": "并发幂等测试111",
    "postIdempotencyKey": "race-001"
}
```

## 幂等实现机制

1. `ch_post` 表的 `post_idempotency_key` 字段上有唯一索引 `uk_post_idempotency_key`，数据库层面保证同一幂等键只能插入一条。
2. `PostServiceImpl.create` 直接执行插入；并发冲突时捕获 `DuplicateKeyException`，按 `post_user_id + post_idempotency_key` 回查并返回已存在的原帖子，保证幂等请求的响应语义一致。

### 单请求成功响应示例

```json
{
    "code": 200,
    "message": "操作成功",
    "data": {
        "postId": 2093630673104351233,
        "postUserId": 2092954516224405506,
        "postTitle": "并发测试",
        "postType": "其他内容",

        "postIdempotencyKey": "curl-probe-001",
        "postViewNumber": 0,
        "createTime": "2026-08-29T09:23:45",
        "updateTime": "2026-08-29T09:23:45"
    }
}
```

### 并发落库验证

8 线程并发携带幂等键 `race-001` 请求后，使用以下 SQL 验证落库结果：

```sql
SELECT post_id, post_idempotency_key, create_time
FROM ch_post
WHERE post_idempotency_key = 'race-001';
```

| 轮次 | 幂等键 | 线程数 | 落库条数 | post_id |
| --- | --- | --- | --- | --- |
| 第 1 轮 | race-001 | 8 | 1 | 2093633534693421057 |
| 第 2 轮 | race-002 | 8 | 1 | 2093634757203013634 |

两轮并发测试中，同一幂等键的 8 个并发请求最终在 `ch_post` 表中都只产生 **1 条**记录，未出现重复插入。

## 测试结论

并发场景下帖子创建接口的幂等设计符合预期：无论多少个线程并发提交同一幂等键，数据库中始终只保留一条帖子记录，由数据库唯一索引兜底，应用层捕获唯一键冲突后返回原帖子。

## 排查记录

测试过程中依次遇到并解决以下问题，留档备查：

| 现象 | 原因 | 解决方式 |
| --- | --- | --- |
| Tomcat 拒绝请求，日志报 `does not conform to RFC 7230` | 请求头写成 `authorization  Bearer: <token>`，Bearer 误入头名称且冒号前有空格 | 改为标准格式 `Authorization: Bearer <token>` |
| 接口返回 401 | Token 抄写错误（结尾多一位字符），Redis 中不存在该会话 | 从登录响应中原样复制 Token |
| 接口返回 404 请求资源不存在 | Docker 镜像陈旧，容器内 jar 未包含 campushub-post 模块 | 执行 `docker compose up -d --build app` 重新构建镜像并重启 |
| 接口返回 415 不支持的媒体类型 | JMeter 消息体数据方式不会自动携带 Content-Type | 信息头管理器中添加 `Content-Type: application/json` |
